## 📢 最新更新

### V1.3.0 版本内容 (2026-09-05)

#### 🛡️ 安全加固（全量代码审查修复）
1. **SSRF 防护（新增）**
   - 远程下载任务仅允许 http/https/ftp/magnet 协议，拒绝 `file://` 及内网/回环/链路本地/云元数据地址（如 `127.0.0.1`、`169.254.169.254`）
   - HTTP 下载使用自定义安全拨号器，**每次连接前校验解析后的真实 IP**，防 DNS rebinding 与重定向绕过
2. **下载管理权限收紧**
   - 下载任务管理、下载统计接口仅**管理员/二级管理员**可用，普通用户不再能创建远程下载任务
3. **任意文件写入防护**
   - BT 种子内文件名、FTP 远端文件名统一清洗（过滤 `../`、控制字符、Windows 保留名，长度截断）
   - 所有协议落盘路径统一安全拼接校验（`SafeJoinFile`），杜绝路径穿越
   - 种子文件上传保存到独立临时目录 `tmp/torrents/` 并清洗文件名
4. **依赖漏洞修复**
   - `disintegration/imaging` v1.6.2 → `vtemlabs/imaging` v1.6.4（**CVE-2023-36308**：TIFF 解码整数越界可致 panic）
5. **密码与统计接口清理**
   - 启动时自动检测并**强制升级明文密码为 bcrypt**（含历史配置文件），`config.json` 及备份文件权限收紧至 0600
   - 密码明文回退比较改恒定时间，消除时序侧信道
   - 移除从未生效的 gin `/stats` 死路由，统计接口统一为 `/api/stats`（文件/分享下载统计，管理员会话或 API Key 认证）

#### ⚙️ 稳定性与并发修复
1. **下载引擎并发安全**：Task 对象广播与持久化前统一深拷贝快照，消除 data race
2. **HTTP 分块下载修复**：修复小文件分块下载必失败的 bug（Go 允许一次 `Read` 同时返回数据与 EOF，原逻辑丢弃末轮数据并误判下载不完整）
3. **任务持久化原子写**：写入改用临时文件 + 原子替换，崩溃不再残留半截 JSON 导致任务丢失
4. **context 生命周期**：下载任务随引擎生命周期正确取消，完成后不再泄漏 context 资源
5. **暂停支持准备阶段**：BT 任务在获取元数据阶段（preparing）也可暂停/恢复
6. **优雅停机**：关闭时通过 WaitGroup 等待下载协程真正退出，不再固定 Sleep
7. **会话读取性能**：会话查询由写锁改为读锁，消除每请求串行化
8. **崩溃自动恢复**：进程强杀/崩溃遗留的 `downloading`/`preparing`/`waiting` 中间态任务，重启后自动重入队恢复下载（`downloading` 按 `.downloading.json` 断点续传）
9. **限速下载修复**：修复令牌桶空转导致的限速下载停滞；移除全局 30s 客户端超时（会掐断慢速限速下载），改为响应头超时 + 任务上下文管理生命周期
10. **IP 下载统计回填修复（09-06 补充）**：历史日志回填仅在 `logs/ip_stats.json` 为空时执行——日志与统计是同一下载事件的双写，旧逻辑只要 `.ip_stats_imported` 标记缺失就把日志再累加一遍，导致**全站下载次数/流量翻倍**；回填改为按 (IP+文件) 60s 合并窗口折算（兼容修复前逐分片计数的旧日志，防虚高）；补扫 `.gz` 轮转压缩日志（防漏统计）；ip_stats 挂入 5 分钟周期兜底落盘（防崩溃丢最近记录）。存量污染数据提供**三种一键修复途径**：IP 管理页「🧰 自检修复」按钮（界面自检+重建）、启动参数 **`-rebuild-ipstats`**、配置项 **`server.rebuild_ipstats_on_boot: true`**（均自动备份 `ip_stats.json.bak.<时间戳>` + 保留封禁状态）
11. **热力图下载热度分片修复（09-06 补充）**：热力图与下载计数同源——旧版每个 Range 分片传输都追加一个 download 数据点，导致活动热力图近 7 天「下载」热度/柱状虚高（与 IP 统计同源的分片重复 bug）。已修复：实时路径热力点移入 (IP+文件) 60s 逻辑下载合并窗口（分片不再加点）；启动加载时对存量污染点做**幂等压缩迁移**（先按时间稳定排序再滑动窗口合并，兼容乱序数据，share 等其他类型不受影响），升级后首次启动自动生效并打印「压缩了 N 条重复热力图 download 点」
12. **文件统计(stats.json)历史重建（09-06 补充）**：首页「累计下载」、文件列表每文件次数、热力图读的都是 `config/stats.json`——旧版每个 Range 分片传输都会 **+1 download_count、追加热力点，并按整文件大小累加 total_bandwidth**，导致比 IP 统计更严重的污染（真实服务器实证：累计 12535 次/30TB → 日志真值 1048 次/43.75GB，次数虚高 12 倍、流量虚高约 690 倍）。已修复：实时路径不再分片累加（含热力点随 #11 一并修正），并新增**按历史日志一键重建 stats.json**——首页「🧰 自检修复」弹窗升级为双卡（IP 统计 + 文件统计/热力图，各自对账与执行修复）；启动参数 **`-rebuild-stats`**；配置项 **`server.rebuild_stats_on_boot: true`**。重建以 (IP+文件) 60s 合并口径从全部日志（含 `.gz`）重算每文件下载次数/带宽/热力点；**分享计数按日志补齐（只增不删，见 #18），上传时间保留原值**，自动备份 `stats.json.bak.<时间戳>`，可重复执行
13. **客户端 IP 来源校验加固（09-06 补充）**：取客户端 IP 时对 `X-Forwarded-For` / `X-Real-IP` 头值做 **IP 格式校验（`net.ParseIP`）**，非法值（伪造头注入任意字符串 / 冒用他人 IP / 携带端口或域名）一律拒绝并回退到 TCP 对端地址——避免伪造 IP 绕过按 IP 下载限额、污染 IP 统计 / 热力图 / 审计日志，从源头阻断存储型注入（展示端另有 HTML/JS 双转义兜底）
14. **登录/协议/角色权限模型重构（09-07 补充）**：
	① **协议页「同意」按角色跳转**：管理员/二级管理员 → 管理后台 `/admin`，普通用户 → 上传界面 `/upload`（原写死跳首页）；
	② **全站解锁机制**：前端（首页 `/`）是否展示下载目录文件由**站点解锁状态**决定——`config.json` 中**任一顶级管理员(role=admin)同意过免责协议即解锁全站**（状态持久化，重启有效），此前首页对匿名/未同意协议完全开放、协议门槛形同虚设；未解锁时首页保持正常观感但**文件区留白**，不渲染任何下载目录内容（含后端预置文件）；
	③ **个人协议关卡**：任何角色登录后未同意协议即被引导到协议页；二级管理员/普通用户的同意仅代表个人确认，**不触发全站解锁**；
	④ **角色权限收敛**：普通用户仅开放上传——登录直达 `/upload` 专用简化界面（无管理侧边栏、不展示下载目录结构、上传进待审核区），访问 `/files`、`/admin`、`/review`、`/user-management` 等一律按角色提示无权限；二级管理员管理后台隐藏「用户管理」「IP管理」（含自检修复）入口与页面（仅顶级管理员可用）；
	⑤ **管理路由入口收敛到后台**：协议页顶部导航不再出现「文件列表/上传文件」等管理链接；首页页脚登录/未登录一致（不再出现使用条款等登录态差异入口）。

15. **下载专用账号锁定 + 二级管理员配额显示修复（09-07 补充）**：
	① **download-user（download 角色）完全锁定**：此账号仅作下载用途——登录接口直接拒绝（即使配置了密码也禁止登录，并修复了此前 download 角色密码验证通过后会**被当普通用户登录并获上传权限**的隐患）；用户管理界面该行「修改密码」显示已锁定、「删除」显示不可删除，服务端接口同步拦截（改名后的 download 角色按 `role=download` 兜底拦截）；
	② **二级管理员配额显示修复**：新增二级管理员时前端以「-1MB」表示无限制，后端存入 `-1048576`，导致用户列表显示「-1048576.00 B」——现创建管理员/二级管理员时后端强制配额为无限制（-1），显示层对 `<=0` 一律显示「无限制」（兼容存量脏值），二级管理员与顶级管理员一致显示「无限制」。

16. **全站交叉审查深挖修复（09-08 补充）**——修复 5 项遗留 BUG + 2 项语义拍板：
	① **文件夹拖拽上传层级丢失（实测坐实）**：上传时浏览器上报的 `relativePath` 原被 `SanitizeFilename`（内部 `filepath.Base`）剥掉子目录，整个文件夹被平铺到所选目录根、不同子目录同名文件会互相覆盖。新增 `SanitizeRelativePath`（按段清洗、保留层级、丢弃 `..` 与绝对路径/盘符），管理端与普通用户（待审区）上传均恢复目录结构；
	② **二级管理员/非 admin 用户名管理员仍受 20GB 日上传总量限制**：配额豁免原写死 `username=="admin"`。现按**角色**判定（`admin`/`subadmin` 无限制），上传页「今日剩余」同步显示「无限制」；上传页「最大文件大小」显示层 `<=0` 即无限制（消除 `-1048576.00 B` 等脏值残留）；
	③ **管理后台协议门控收敛为全局中间件**：原仅 `/admin` `/files` `/upload(GET)` 检查 `AgreedToTerms`，管理员未同意时手输 `/review` `/logs` `/ip-management` 等 URL 即可绕过协议关卡。新增 `AdminAgreementMiddleware`——已登录的管理员/二级管理员未同意协议时，访问**任意后台路由一律重定向 `/terms`**（放行 `/terms` `/agree-terms` `/login` `/logout` `/static/`）；
	④ **下载通道纳入站点锁**（拍板：锁定期间禁止任何取文件）：`/download` 直链与 `/s/` 短链在站点未解锁（无任何顶级管理员同意协议）时直接返回 403「站点内容暂未开放」，不再存在「首页留白但知道直链/旧短链仍可下载」的绕过；解锁后恢复正常；
	⑤ **单删与批删语义统一为「保留 pending」**（拍板）：单文件删除不再连带清理各用户 pending 目录下的同名待审副本（原实现会误删普通用户尚未审核的独立上传），与批量删除行为一致；
	⑥ **登出日志角色补齐**：subadmin/download 角色登出不再被记为 `unknown`。

17. **生产反馈修复（09-08 补充）**——日志中文 + 首页分享计数漏接：
	① **日志动作中文化缺失**：日志页 `actionMap` 缺 8 个代码真实使用的动作键（`batch_move`/`batch_copy`/`search_files`/`short_url_created`/`short_url_deleted`/`short_url_probe`/`rebuild_file_stats`/`rebuild_ip_stats`），未命中的动作在日志页原样显示英文。已补全中文映射（纯显示层，不改日志存储格式）；
	② **首页分享不计入统计（实测坐实）**：`/files` 管理页与搜索结果页的分享按钮均调用了 `/api/increment-share` 计数接口，唯独首页（IndexHandler 内嵌 JS）只有 `generate-short-url`、漏接计数调用 → 首页分享后文件统计「分享次数」与热力图 share 点均无数据。已在首页短链生成成功分支补 `fetch('/api/increment-share?path=...')`（与 /files 页语义一致：短链生成成功即计 1 次，不依赖 clipboard 结果，避免重复/漏计）。本地实证：首页分享 → 热力图立即出现 `type:"share"` 点。

18. **分享计数口径统一 + 自检修复补齐历史分享（09-08 拍板，面向升级部署的通用修复）**——任何旧版（首页分享漏接计数）部署升级后，都可用自检修复把历史分享从日志补齐：
	① **实时分享计数去重（口径变更）**：`/api/increment-share` 对**同 IP × 同文件 × 同一天只计 1 次**（不同文件互不影响），去重状态持久化进 `config/stats.json`（`share_daily_dedup` 字段，重启不丢失、每日自动清理过期记录）——既防前端重复触发，也防接口被无鉴权直刷虚增计数/热力点；
	② **自检修复补齐历史分享（方案 A：只补不删）**：文件统计重建（界面「🧰 自检修复」/ `-rebuild-stats` / `rebuild_stats_on_boot`）新增解析日志中 `short_url_created` 记录，按与实时一致的口径（同 IP × 同文件 × 同天 = 1 次）统计**分享日志真值**；对每个文件 `ShareCount = max(现有值, 日志真值)`——把首页漏接计数造成的缺失补上，同时保留日志保留期外/接口直刷的既有值（不削减）；share 热力点按 (文件+IP+日期) 差集补漏，已有点不重复追加；幂等（重建后再跑结果不变，每次仍自动备份）；
	③ **对账可视化**：自检修复弹窗文件统计卡新增「当前分享 vs 日志分享真值」展示与独立判定徽标（分享缺失 → 提示补齐；当前高于日志 → 提示保留现值不削减）；执行修复后结果内联展示分享补齐数。

### V1.2.0 版本内容 (2026-09-03)

#### 🔐 密码安全升级（bcrypt哈希）
1. **bcrypt密码哈希存储**
   - 新用户添加时自动使用 bcrypt 哈希密码
   - 修改密码时自动使用 bcrypt 哈希新密码
   - 使用 `bcrypt.DefaultCost`（成本因子10），安全性和性能平衡
   - 配置文件中密码不再明文存储

2. **平滑迁移（兼容现有明文密码）**
   - 现有用户密码保持明文，不影响登录
   - 用户登录成功后，**自动异步升级**为 bcrypt 哈希
   - 升级过程不阻塞登录响应，用户无感知
   - 首次登录升级后，后续登录使用 bcrypt 验证

3. **兼容验证**
   - `VerifyPassword` 函数自动识别密码格式
   - bcrypt 哈希（`$2a$`/`$2b$`/`$2y$` 开头）→ 使用 bcrypt 验证
   - 明文密码 → 直接比较
   - API 认证也兼容 bcrypt 密码

#### 🌐 IP下载管理系统（新增）
1. **IP下载统计**
   - 自动记录每个IP的下载次数、总流量、首次出现时间、最后下载时间
   - 数据持久化存储到 `logs/ip_stats.json`
   - 支持按最后下载时间排序展示

2. **IP封禁/解封管理**
   - 支持手动添加封禁IP（输入IP地址和封禁原因）
   - 支持对已有IP进行封禁/解封操作
   - 被封禁IP无法下载文件，返回403 Forbidden
   - 封禁原因记录到操作日志

3. **IP流量限额配置**
   - 支持配置每日下载次数限制、每日下载流量限制
   - 支持配置每小时下载次数限制、每小时下载流量限制
   - 超过限额返回429 Too Many Requests
   - 支持自动封禁功能，超过限额时自动封禁IP

4. **历史日志自动回填（机制已在 V1.3.0 修正）**
   - 仅当 `logs/ip_stats.json` 尚无任何数据时，启动自动从历史日志重建 IP 统计——此时日志是唯一统计来源，不会与实时双写重叠
   - 回填按 (IP+文件) 60s 合并窗口折算「逻辑下载」次数，带宽逐行累加，兼容修复前逐分片计数的旧日志（防虚高）
   - 支持扫描 `.gz` 轮转压缩日志，超 10MB 归档的历史不遗漏
   - 已有统计数据（程序正常运行过）即跳过回填，杜绝同一事件被实时与回填重复计数

5. **下载统计自检修复（V1.3.0 新增，面向升级部署）**

- **路径安全**：生成前验证路径安全，防止路径遍历
- **短链管理**：管理端支持查看和删除短链
- **友好提示**：短链不存在或已过期时，显示美观的提示页面，3秒后自动跳转到首页

### 🛡️ 安全防护措施

#### 1. XSS 跨站脚本防护
- **HTML编码**：对所有用户输入进行HTML实体编码
- **HTML清理**：移除危险标签（script、style、iframe等）和事件处理属性
- **URL验证**：验证和清理危险URL协议（javascript:、vbscript:等）
- **属性安全**：对HTML属性值进行安全处理，防止属性注入
- **全页面覆盖**：应用到文件列表、用户管理、日志页面、管理员界面等所有关键页面

#### 2. CSRF 跨站请求伪造防护
- **安全令牌**：使用 `crypto/rand` 生成32字节安全令牌
- **常量时间比较**：防止时序攻击
- **双渠道支持**：支持表单隐藏字段和AJAX请求头两种方式
- **全操作覆盖**：应用到用户管理、文件操作、分类管理、下载任务API、登录表单等所有关键操作
- **公开接口豁免**：公开分享计数接口保持匿名豁免

#### 3. 路径遍历防护
- **8步严格验证**：清理路径、检查`..`、获取绝对路径、验证是否在基础目录内等
- **全路径覆盖**：应用到文件下载、文件浏览等所有路径相关操作
- **符号链接检查**：可选的符号链接目标验证

#### 4. 访问控制
- **严格的权限验证**：实时验证用户权限，防止未授权访问
- **多角色支持**：四种登录角色（管理员/二级管理员/普通用户/下载专用 download-user），另有未登录访客浏览已解锁站点
- **站点级门控**：全站解锁（任一顶级管理员同意协议）决定前端文件与下载通道是否开放；后台协议门控中间件统一拦截未同意协议的管理员/二级管理员
- **细粒度权限**：针对不同角色分配不同的操作权限

#### 5. 会话管理
- **HttpOnly Cookie**：防止XSS攻击窃取会话
- **SameSite 属性**：防止CSRF攻击
- **Secure 属性**：HTTPS时启用，保护数据安全
- **24小时自动过期**：定期清理过期会话
- **密码修改失效**：密码修改时自动失效相关会话
- **安全会话ID**：使用 `crypto/rand` 生成安全的会话ID

#### 6. 密码安全
- **bcrypt哈希存储**：新用户和修改密码时自动使用bcrypt哈希，防止密码泄露
- **平滑迁移**：现有用户登录后自动升级为bcrypt哈希，不影响使用
- **兼容验证**：自动识别明文和bcrypt哈希，兼容现有配置
- **独立API Key自动生成**：首次启动服务器时自动生成随机API Key（64字符十六进制），不再直接比对管理员明文密码；已存在配置文件时不覆盖

#### 7. 混合内容修复（HTTPS安全）
- **协议自动识别**：新增 `GetRequestScheme()` 函数，优先检查 `X-Forwarded-Proto` 头，其次检查 `r.TLS`
- **图标URL修复**：文件列表图标URL、图标处理器URL统一使用当前请求协议
- **短链URL修复**：短链生成API的FullURL从硬编码 `http://` 改为动态获取当前协议
- **适用场景**：Nginx/Caddy/Traefik等反向代理HTTPS部署时，所有资源链接自动适配HTTPS

#### 8. 反向代理真实IP获取
- **直接信任代理头**：`GetClientIP()` 函数直接检查 `X-Forwarded-For` 和 `X-Real-IP` 请求头
- **多代理链支持**：正确解析 `X-Forwarded-For` 中的多个IP，取第一个为真实客户端IP
- **日志记录准确**：用户登录、文件访问、下载等操作日志中记录真实IP

#### 9. 文件安全
- **文件类型检查**：阻止危险文件上传
- **文件大小限制**：根据用户角色设置不同的文件大小限制
- **每日上传限制**：普通用户20GB/日上传限制

#### 10. SSL支持
- **HTTPS加密传输**：支持HTTPS加密传输，保护数据安全
- **证书配置**：支持配置证书文件和私钥文件

#### 11. SSRF 防护（v1.3.0 新增）
- **协议白名单**：远程下载仅允许 http/https/ftp/magnet，拒绝 file://
- **内网地址拒绝**：解析目标 host 后拒绝 loopback / private / link-local / IPv6 ULA / 云元数据地址
- **拨号前校验**：自定义 Transport 在每次连接前校验解析后的真实 IP，防 DNS rebinding 与重定向绕过

#### 12. 远程文件名安全（v1.3.0 加固）
- **统一清洗**：BT 种子内文件名、FTP 远端文件名、HTTP 文件名统一过滤 `../`、控制字符、Windows 保留名并截断长度
- **安全落盘**：所有协议写入路径经 `SafeJoinFile` 前缀校验，杜绝路径穿越
- **下载管理鉴权**：下载任务管理/统计接口仅管理员与二级管理员可用（v1.3.0）

### 📝 日志系统
- **多级日志记录**：支持success、error、warning、debug和info五种日志级别
- **详细日志内容**：记录用户操作、系统事件和错误信息

#### 方式一：从源码编译
```bash
# 克隆仓库
git clone https://github.com/gomail1/go-download.git
cd go-download

go build -o go-download .

./go-download
```

#### 方式二：使用 Docker（推荐）

支持多架构镜像（amd64 + arm64），自动适配服务器架构。

```bash
# 拉取镜像（自动适配架构）
docker pull gomail1/go_downloader:latest

# 运行容器
docker run -d \
  --name go-download \
  --restart unless-stopped \
  -p 9980:9980 \
  -p 1443:1443 \
  -v /path/to/downloads:/app/downloads \
  -v /path/to/pending:/app/pending \
  -v /path/to/logs:/app/logs \
  -v /path/to/config:/app/config \
  -v /path/to/ssl:/app/ssl \
  -e TZ=Asia/Shanghai \
  gomail1/go_downloader:latest
```

```yaml
version: '3.8'
services:
  go-download-server:
    image: gomail1/go_downloader:latest
```

所有需要鉴权的接口都需要：

## 🛠️ 技术栈

### 后端技术
- **后端语言**：Go 1.27+
- **Web框架**：标准库 `net/http`（主服务）+ Gin（下载任务API）
- **数据库**：JSON文件存储（无需外部数据库，轻量级部署）
- **WebSocket**：`github.com/gorilla/websocket`（实时推送下载进度）
- **日志库**：`github.com/sirupsen/logrus`（结构化日志）
- **配置管理**：`github.com/spf13/viper`（灵活的配置管理）
- **文件系统监控**：`github.com/fsnotify/fsnotify`（文件变更监控）
- **加密库**：`golang.org/x/crypto`（bcrypt密码哈希、安全加密）
- **图像处理**：`github.com/disintegration/imaging`（图标缩放处理）
- **TUI框架**：`github.com/charmbracelet/bubbletea` + `bubbles`（终端用户界面）

### 前端技术
- **前端**：原生 HTML + CSS + JavaScript（无框架依赖，轻量级）
- **图表库**：Chart.js（本地部署，无外部CDN依赖）
- **响应式设计**：6级媒体查询断点，适配桌面端和移动端
- **全平台支持**：Windows、Linux、macOS、Android、iOS

### 下载协议
- **HTTP/HTTPS**：标准库实现，支持多线程加速（最大100线程，默认10线程）与断点续传
- **BitTorrent**：`github.com/anacrolix/torrent`，支持磁力链接与种子文件，实时显示连接节点数
- **FTP**：标准库实现，PASV被动模式 + RETR流式拉取
- **文件完整性验证**：下载完成后自动验证文件完整性（MD5/SHA256），避免下载出异常文件
- **图标缓存**：自动提取Windows可执行文件图标，缓存到配置目录，前端展示真实程序图标

### 安全防护
- **XSS跨站脚本防护**：自定义实现，HTML编码、危险标签清理、URL验证
- **CSRF跨站请求伪造防护**：自定义实现，基于会话ID的令牌机制（含登录表单）
- **路径遍历防护**：自定义实现，8步严格验证
- **会话管理**：HttpOnly、SameSite、Secure属性，24小时自动过期
- **密码安全**：bcrypt哈希存储，平滑迁移，兼容验证
- **独立API Key**：首次启动自动生成随机API Key

### 监控与运维
- **系统监控**：自定义实现，CPU、内存、磁盘使用率实时监控
- **跨平台磁盘监控**：条件编译，Windows使用GetDiskFreeSpaceExW，Linux/Mac使用syscall.Statfs
- **告警系统**：支持配置告警阈值，超过阈值自动触发告警
- **Gzip压缩**：中间件实现，压缩HTML、CSS、JavaScript等文本资源
- **静态资源缓存**：根据文件扩展名设置不同缓存时间
- **容器化**：Docker支持，多架构镜像（amd64+arm64），一键部署

### 测试与质量
- **测试框架**：标准库 `testing`
- **测试覆盖**：安全工具、路径验证、CSRF防护、XSS防护、短链安全等
- **代码风格**：`CODE_STYLE.md` 规范，统一代码风格
- **并发安全**：`sync.RWMutex` 保护共享数据，原子写配置文件
